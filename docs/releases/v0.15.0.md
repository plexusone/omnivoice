# Release Notes: v0.15.0

**Release Date:** 2026-11-13

## Summary

Adds speech synthesis to the command line, and pronunciations for names and
terms that a voice says wrong. `omnivoice speak` writes text to an audio file
with any TTS provider; `omnivoice voices` finds a voice. A pronunciation is
IPA, a respelling, or both: each provider uses the IPA where its voice or
model accepts phonemes and the respelling otherwise, so the same
pronunciations work across providers.

## Highlights

- **`omnivoice speak`**: synthesize text, from an argument or standard
  input, to MP3, WAV, Opus or PCM, with pronunciations from a
  terminology-spec terms directory or from `--ipa` and `--say`
- **`omnivoice voices`**: list a provider's voices, filtered by name,
  language, accent or description with `--match`, as text or JSON
- **Pronunciations**: `SynthesisConfig.Pronunciations` carries each term's
  IPA and respelling to the provider

## Added

- `omnivoice.Pronunciation` and `omnivoice.ApplyPronunciations`,
  re-exported from omnivoice-core
- `speak` flags: `--voice`, `--output`, `--provider`, `--model`, `--locale`,
  `--terms`, `--ipa`, `--say`, and `--phonemes` (`auto`, `on` or `off`) for
  ElevenLabs
- `voices` flags: `--provider`, `--match` and `--json`
- `speak` with providers that don't apply pronunciations, such as OpenAI and
  Deepgram, puts the respellings into the text
- `speak` checks the audio against the output's extension: raw PCM for a
  `.wav` gets a WAV header, and a provider that can't return the format,
  such as ElevenLabs for `.opus`, is an error with nothing written
- `speak` and `voices` need an API key only for providers that require one

## Provider Changes

### ElevenLabs (elevenlabs-go v0.15.0)

- Pronunciations sent as SSML phoneme tags on `eleven_flash_v2`,
  `eleven_turbo_v2` and `eleven_monolingual_v1`, and as respellings on other
  models
- The pronunciation dictionary, previous text and next text extensions are
  now sent with the request

### omnivoice-core (v0.19.0)

- `SynthesisConfig.Pronunciations` and `ApplyPronunciations`
- `terminology.PronunciationsFor` turns terminology-spec terms, which can now
  carry IPA, into a request's pronunciations

## Dependencies

- Requires `github.com/plexusone/omnivoice-core` v0.19.0 and
  `github.com/plexusone/elevenlabs-go` v0.15.0
- `speak --terms` reads terminology-spec v0.2.0 terms, with IPA
- Indirect dependencies updated

go get github.com/plexusone/omnivoice@v0.15.0

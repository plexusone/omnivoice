# Release Notes: v0.16.0

**Release Date:** 2026-11-17

## Summary

Adds checking quotations against a recording to the command line. One
engine's transcript can't show which of its words are wrong, so `omnivoice
verify quotes` has several engines hear a short clip around each quotation
and compares what they heard with fixed rules. A quotation every engine
heard is `agreed`; one they all heard differently is `corrected`, with their
wording; one they disagree on, where the word matters, is `disputed` and
needs a person or a judge to listen.

## Highlights

- **`omnivoice verify quotes`**: checks quotations against a recording with
  Deepgram, ElevenLabs and OpenAI, writing a JSON report and a summary
- **`omnivoice verify absence`**: searches independent transcripts before
  saying a recording doesn't mention something
- **Language codes and WAV clips work with every provider**, through
  elevenlabs-go v0.15.1 and omni-openai v0.8.1

## Added

### `verify quotes`

```bash
omnivoice verify quotes --audio episode.mp3 --index episode.json \
  --quotes quotes.json -p deepgram,elevenlabs,openai -o report.json
```

- Quotations come from `--quotes`, a JSON array of `{"id", "text",
  "start_ms", "end_ms"}` with optional times, or from `--quote`, repeated.
  A quotation without times is located in the `--index` transcript.
- Each quotation is clipped with `--pad` (1.5 s) on each side and
  transcribed by every engine in `--providers`. `--min-engines` (3) sets how
  many must succeed.
- Decisions:

  | Decision | Meaning |
  |----------|---------|
  | `agreed` | Every engine heard the quotation |
  | `corrected` | The engines agree with each other but not with the quotation |
  | `disputed` | They disagree on a number, negation, name, term or other substantive word |
  | `notFound` | The quotation could not be located in the recording |
  | `insufficient` | Too few engines produced a transcript |

- The summary on stderr lists each quotation's decision and clip, the
  engines' wording for a correction, and each substantive word they
  disagree on.
- Key words come from `--keyword` and a terminology-spec `--terms`
  directory, whose aliases are also accepted as matches. They are never
  taken from the quotation, and `--plain-engine` (by default the last
  provider) runs without them.
- `--model provider=model` chooses a model per engine.

ffmpeg must be on `PATH`. Confirm names, titles and dates from a written
source, whatever the engines hear.

### `verify absence`

```bash
omnivoice verify absence --transcript deepgram.json --transcript openai.json \
  --phrase "locally" --phrase "on my laptop"
```

The result says how many transcripts have each phrase, never that the
recording lacks it. With one transcript, it warns that a phrase it lacks may
still be in the recording.

## Dependencies

- Requires `github.com/plexusone/omnivoice-core` v0.20.0, which adds the
  verify package
- `github.com/plexusone/elevenlabs-go` v0.15.1 and
  `github.com/plexusone/omni-openai` v0.8.1, which send each service the
  language codes it accepts, and name OpenAI uploads so WAV clips are
  recognized
- `github.com/grokify/mogo` v0.75.0, now a direct dependency
- Indirect dependencies updated

## Installation

```bash
go get github.com/plexusone/omnivoice@v0.16.0
go install github.com/plexusone/omnivoice/cmd/omnivoice@v0.16.0
```
